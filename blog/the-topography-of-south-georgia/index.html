The Topography of South Georgia

And How I Made it in Blender

January 1, 2019

South Georgia is a mountainous island in the South Atlantic. Its rugged landscape is home to diverse wildlife, towering fjords, and numerous glaciers—the latter of which outnumber the island’s seasonal population of humans.

While working on a project that made us of South Georgia’s terrain, I took a moment to produce a topographic relief map in Blender.

In addition to the map, I also wanted to share a bit about how it was made.

A render of South Georgia Island with long shadows. View larger.

This tutorial assumes you have some familiarity with the following:

  • Blender and the nodes interface
  • GDAL (or equivalent ability to merge and reproject rasters in GIS)

Making the map

The render above was made from Shuttle Radar Topography Mission (SRTM) data. SRTM is a digital elevation model (DEM), available for much of the globe (between 56° S and 60° N). It is available in spatial resolutions of 30 and 90 meters.

SRTM data is essentially an image, where pixel values represent terrain height (in meters).

Elevation data of South Georgia Island. Higher elevations are shown in in white. For clarity, values have been scaled across the 16-bit integer range (0-65536).

Getting elevation data

The easiest way to get SRTM data is through SRTM Tile Downloader, a phenomenal tool made by Derek Watkins. In order to download the SRTM data, which comes from NASA and the U.S. Geological Survey, you will need a free NASA Earthdata account.

SRTM Tile Downloader makes it a breeze to acquire elevation data.

Downloading the data from SRTM Tile Downloader is as simple as clicking the tile(s) you want and selecting ‘Download DEM.’

The example above shows the main island of South Georgia requires six tiles.

Data prep (partly optional)

Before the data are ready for Blender, two things need happen for convenience and better representation of the geography.

1: If multiple tiles are used, they need to be merged into a single DEM.

The easiest way to do this is through the Geospatial Data Abstraction library, better known as GDAL.

Once the tiles are unzipped to reveal a number of .hgt files, they can be merged into one seamless file like so:

$ gdal_merge.py -n -32768 -o merged_dem.tif *.hgt

This produces a new file called ‘merged_dem.tif.’ The -n -32768 option tells gdal_merge to use -32768 as no-data values, essentially ignoring those values and allowing the input images to overlap one another seamlessly.

2: The DEM should be reprojected.

SRTM data comes georefferenced in WGS84, which is not the best choice for large scale mapping. Depending on the area of interest, a variety of map projections would be suitable. For my map it was important to preserve the shape of South Georgia. I opted for Universal Transverse Mercator (UTM), which is a conformal projection. (To see a map of UTM zones, go here.)

South Georgia is within UTM zone 24 South. This projection can be identified by EPSG:32724.

To reproject the data to UTM 24 S, I used GDAL again:

$ gdalwarp -t_srs EPSG:32724 merged_dem.tif projected_dem.tif
Tip: The EPSG code for UTM zones has the form 32YZZ.

Y = 6 for the northern hemisphere, 7 for the south. ZZ = two-digit UTM zone.

For other projections, I’d recommend exploring Projection Wizard.

Shaded Relief in Blender

Now the fun can really begin: unleashing the power of Blender! In particular, we’re going to make use of two features of Blender: the cycles render engine and adaptive subdivision.

Adaptive subdivision is a somewhat new feature in Blender. It allows a mesh to be subdivided (i.e. increase the number of faces and vertices) nonuniformly across the object. As a result, rugged terrain surfaces can have a higher density of vertices than flat terrain, allocating resolution and detail to where it is needed most. Through the OpenSubdiv option, adaptive subdivision also accounts for viewing distance. In oblique views, terrain closest to the camera will be subdivided more than distant terrain.

In contrast to a standard uniform subdivision, adaptive subdivision increases detail in the most visible areas, while reducing the number of unnecessary vertices. This increase in detail is visually stunning, while also being computationally more efficient. It is truly a win-win!

The basic approach to creating a relief map in Blender is:

Create a plane subdivide the plane displace the subdivisions using elevation data

So let’s do that!

Blender Setup

Start up Blender and create a new project. Delete the default cube.

In order to use the features necessary for this map, change the rendering engine to Cycles Renderer, and then change the feature set to Experimental. The experimental feature set provides access to adaptive subdivision. (It’s up to you—and your computer—whether to use CPU or GPU for rendering. Either will work fine!)

We start off by enabling cycles and the experimental feature set.

Now create a plane. The default location (0, 0, 0) is perfect. But we’ll need to change the X and Y scale of the plane so it matches the width and height of the elevation image.

Caution! By default, Blender units will not be the same as pixel sizes. That's OK! What matters is that we get the correct aspect ratio.

My merged and projected DEM of South Georgia is an image that is 8946 x 5032 pixels. If I made an 8946 x 5032 plane in Blender, using the default units, the plane would be ginormous—much too large for the scene and camera. Instead, I can simplify things by making a plane that is 1000 times smaller: 8.946 x 5.032.

The dimensions of the plane must have the same aspect ratio as the elevation image.

In general, you want the X and Y scales to be less than 20. The raw values don’t matter, as long as the aspect ratio and proportions remain correct. The Z scale can be left alone at 1.0.

With a plane created and scaled to the right size, it is time to start setting up the adaptive subdivision.

With the plane still selected, go to the Modifiers panel and select Subdivision Surface from the dropdown.

A subdivision surface modifier prepares the plane for a rugged future.

Once the subdivision surface modifier has been added, the plane will initially appear distorted. A couple more settings need to be changed.

In the options for the subdivision surface modifier, change the mode to Simple, and check the boxes for Adaptive and Use OpenSubdiv.

Setting the settings.

The Simple option returns the plane to its original shape. This ensures the geometry of the plane remains unchanged without any smoothing or generalization.

Adaptive is the real MVP here: this is the setting that allows the plane to subdivided at different resolutions, depending on the complexity of the displacement. More subdivisions will be made where the displacement varies most (e.g., rugged terrain).

By checking Use OpenSubdiv, Blender uses a high-performance subdivision approach developed by Pixar. If your system supports it, Opensubdiv will greatly improve the performance of the subdivision, and account for camera distance in addition to the complexity of the displacement.

Other settings, like Dicing Rate, can be left unchanged. The Dicing Rate scales the number of subdivisions. Smaller numbers will result in many more subdivisions. If the DEM resolution is high, lowering this value can bring even more detail to the final render (at the expense of additional rendering time).

Getting Bumpy: Displacing the Plane

We have a plane. It is prepared for subdivision. Now we need to influence the height of the subdivisions based on the elevation data.

To do that, we’re going to feed the SRTM imagery to the plane as an image texture, using the image as a displacement map.

Go to the plane’s Materials tab and click new to assign it a new, default material.

Under the new material’s settings, change the Displacement to True. This allows the displacement to affect the actual geometry of the plane.

Assigning the plane a material and enabling true displacement.

Now the fun can begin!
