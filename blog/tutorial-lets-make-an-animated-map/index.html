Tutorial: Let's Make an Animated Map

August 26, 2022

It wouldn’t be the internet as we know it without GIFs. And GIFs of maps.

We know them, we love them… but how do we make them?

This tutorial will show you how to quickly create an animated map using QGIS and GDAL. Whether you have four frames or four thousand, the process is straightforward. And you won’t need to make a single screenshot!

Background and Pre-Reqs

Gone are the days when a static view of some (probably old) data is a cartographic default. There’s petabytes of data out there, and a great deal of it is acquired in near-real time with high temporal frequency. Wind patterns, hourly rainfall, and daily temperatures just begin to scratch the surface. The data are there. But processing it and producing a quality animation can seem daunting.

It is somewhat of a cartographic coming-of-age ritual to approach the task of animating a map by manually taking dozens of screenshots and stitching them together. We have all done it, and it is a practice that lives on in newsrooms today.

But there is a better way! Let me show just how easy it can be.

First things first, there are a few things you will need.

  1. Some temporal data. (Don’t have that? I’ve got you covered. Download these example files of XXXXXX…)
  2. QGIS
  3. GDAL and comfort using the command line—or at least a willingness to try
  4. Photoshop, ffmpeg, imagemagick, or video software of your choice

Step 1: Thinking of a Map Sandwich

Before processing any data, we first have to understand what we’re about to do. And the easiest way to think of it is this: we’re going to create a map sandwich.

Every map is the product of layers. This is especially true of animated maps, and approaching this task knowing there will be layers is key. What makes animated maps a bit different than others is that only some layers need to animate. In this tutorial we’re only going to be animating a single layer. The others can remain static.

This is where the map sandwich comes in.

Like your favorite hoagie, sub, melt, or burger, an animated map is a stack of ingredients built from the bottom up. You can think of it something like this:

  • Top layer: Some reference data - borders, cities, labels, and so on.
  • Middle layer: The thematic data to be animated.
  • Bottom layer: The base map. Maybe terrain, land/water masks, or just a blank canvas.

Conceptualizing the project in this way greatly simplifies the task. For instance, imagine we have a detailed terrain map and we wanted to overlay it with animated soil moisture over hundreds of days, while also showing state and/or country borders. The terrain doesn’t change. The borders aren’t going to change. So there is no need to draw that information over and over again hundreds of times. Instead, a single base map can be rendered as a still image, followed by an image that is just the borders over a transparent background. And then the animated data can be slipped in between those two images.
